# П.1. Анализ требований и предметной области

## Вариант задания

**Вариант 12 — ROT13**

## Предметная область

ROT13 (rotate by 13 places) — симметричное преобразование строки, при котором каждая **латинская** буква заменяется буквой алфавита, отстоящей на 13 позиций от исходной. Число 13 выбрано потому, что для алфавита из 26 букв двойное применение возвращает исходный текст (**самодвойственность**): \(E(E(x)) = x\).

Исторически ROT13 применялся в новостных системах и форумах для сокрытия спойлеров и юмора «намеренно слабым» способом: это не криптографическая защита, а обфускация чтения.

## Функциональные требования

| ID | Требование |
|----|------------|
| F1 | Реализовать метод преобразования `Rot13(string text)` для строки UTF-16 (тип `string` в C#). |
| F2 | Сдвиг на 13 позиций только для латинских букв `A–Z` и `a–z`. |
| F3 | Символы вне латинского алфавита (цифры, пробелы, знаки препинания, кириллица и др.) **не изменяются**. |
| F4 | Шифрование и дешифрование совпадают по алгоритму (**самодвойственность**). |
| F5 | В приложении выделить **два модуля**: шифрование и дешифрование (отдельные классы), вызывающие общую логику ROT13. |

## Нефункциональные требования

| ID | Категория | Требование |
|----|-----------|------------|
| NF1 | GUI | Наглядное разделение операций шифрования и дешифрования, подписи полей, кнопки действий. |
| NF2 | Удобство | Всплывающие подсказки (ToolTip) для полей ввода и кнопок. |
| NF3 | Надёжность | Обработка `null`, пустых и пробельных строк, некорректной длины ввода без аварийного завершения процесса. |
| NF4 | Сопровождение | XML-документация публичных членов моделей и обработчиков UI. |
| NF5 | Безопасность (уровень учебного приложения) | Ограничение максимальной длины ввода для снижения риска чрезмерного потребления памяти при обработке очень длинных строк. |

## Ограничения и допущения

- Язык реализации: C#, платформа: .NET Framework 4.7.2, UI: WPF.
- ROT13 не предназначен для защиты данных; модель угроз не рассматривается как для криптосистемы.
- Поведение для `null`: на уровне ядра — исключение `ArgumentNullException`; на уровне UI — сообщение пользователю (поле не должно передавать `null` в обычном сценарии).

## Критерии приёмки (кратко)

- Автотесты подтверждают самодвойственность и неизменность неалфавитных символов.
- Ручная проверка подтверждает корректность интерфейса и сообщений об ошибках.
